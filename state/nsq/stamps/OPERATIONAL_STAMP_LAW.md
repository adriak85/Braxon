# OPERATIONAL STAMP LAW

A stamp is not passive metadata.

A stamp is an operational wake trigger.

A valid stamp must be capable of initiating:

stamp
→ wake packet
→ route resolution
→ framework retrieval
→ reconstruction/materialization
→ execution
→ persistence/update

A stamp without operational behavior is incomplete.

Metadata alone is not execution.

Execution claims require:
- runtime causality
- operational proof
- materialization/reconstruction proof
- execution proof
- persistence/update proof

Invalid states:
- passive-only stamps
- archive-only stamps
- metadata-only runtime claims
- fake hot-live state
- placeholder execution claims
- unresolved wake chains
- unresolved route resolution
- unresolved materialization
- unresolved execution

Runtime truth takes priority over reporting convenience.
