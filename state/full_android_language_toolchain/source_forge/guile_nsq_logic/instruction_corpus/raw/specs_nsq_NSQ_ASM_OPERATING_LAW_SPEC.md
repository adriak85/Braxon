# NSQ ASM Operating Law Specification

## Required Invariant

NSQ remains canonical source truth.

ASM is the operating, recode, and optimization law.

Binary is a downstream Braxon translation output.

## Required Processing Order

1. Read everything available.
2. Check surroundings and full context.
3. Identify all aspects of all perceivable; continue until the system is sure it knows everything it can about everyone and everything around the action.
4. Understand action from all viewpoints, including the system's own viewpoint.
5. Make the best decision.
6. Act with the very best of being.

## Incoming Material Rule

Every incoming supported source surface must be tracked as source material, passed through NSQ authority, then recoded toward ASM operating form.

Supported incoming material may include Rust, C, Python, shell, markdown, JSON, TOML, TSV, NSQ, and other documented surfaces, but no incoming surface becomes NSQ authority by itself.

## ASM Rule

ASM operating form must include:

- source path
- source hash
- authority role
- recode tool identity
- generation round
- dependency and reverse-dependency tracking
- validation status
- moral-invariant preservation status

## Binary Rule

Braxon may translate ASM operating forms into binary only as downstream output.

Binary output must not be written back as NSQ source authority unless explicitly represented as a generated artifact with preserved lineage.

Binary output must not override the moral invariant.

## Guard Recursion Rule

The moral guard must guard the guard.

The guard loop must check:

- the protected moral invariant
- the guard tool
- the guard carriers
- the ASM operating law
- the metadata law
- the binary boundary

A contradiction requires failure.

## Completion Honesty Rule

The presence of metadata, ASM operating law, or binary translation rules does not mean Braxon is complete.

The repository may say the pipeline is installed, staged, tested, or partially operational only when the corresponding proof exists.
