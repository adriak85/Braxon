# NSQ Stack-Surface Registry

## Purpose

The stack-surface registry is the native inventory of external and adjacent practical surfaces that Braxon must understand.
It is not a plugin forest and not a loose guess list.

## Required classes

- language
- build_grammar
- runtime_interface
- artifact_container
- database_query
- boot_control
- graphics_render
- tooling_automation
- filesystem_surface

## Registry responsibilities

- assign each stack surface a stable class
- link each stack surface to one or more language-master surfaces
- define boundary projection rules for foreign tools
- define which court and watcher outputs are relevant for that surface

## Minimum seeded surfaces

The registry must cover the high-value surfaces already identified in Braxon work:
Python, Lua, Lisp family, C family, Java/Kotlin, shell families, build grammars, Android toolchains, graphics surfaces, boot/control surfaces, artifacts, databases, and system interfaces.
