# BRAXON / NSQ RUNTIME DEFINITIONS

## NSQ

NSQ is not:
- byte semantics
- u8 semantics
- flattened integer routing
- ordinary tokenizer semantics
- passive metadata topology

NSQ is:
- semantic-state execution topology
- operational semantic routing
- runtime causality substrate
- gradient-addressable execution structure
- persistent semantic state field
- semantic wake execution system

## BRAXON

Braxon is:
- a canonical runtime authority system
- a semantic execution runtime
- an operational wake-routing system
- a runtime materialization structure
- a semantic reconstruction system
- a persistence-aware execution field

Braxon is not:
- a reporting shell
- a placeholder orchestration layer
- a metadata-only architecture
- a passive semantic archive
- a plugin-wrapper forest

## STAMPS

Stamps are:
- operational wake triggers
- semantic routing initiators
- execution-start surfaces
- framework wake calls
- materialization/reconstruction triggers

Stamps are not:
- passive labels
- symbolic-only metadata
- archive-only references
- reporting-only surfaces

## MATERIALIZATION

Materialization means:
- operational reconstruction
- executable realization
- runtime-capable assembly
- semantic execution readiness

Materialization is not:
- manifest-only presence
- metadata registration
- symbolic declaration
- placeholder reporting

## HOT-LIVE

Hot-live state requires:
- runtime causality
- operational proof
- execution capability
- materialization proof
- semantic continuity

Manifest-only state is not hot-live.

## SEMANTIC ROUTING

Semantic routing:
- resolves operational execution paths
- preserves semantic causality
- preserves execution continuity
- preserves runtime authority

Semantic routing is not:
- flattened token routing
- ordinary integer dispatch
- simplistic command matching

## EXECUTION TRUTH

Execution truth requires:
- actual operational behavior
- execution evidence
- runtime causality
- persistence/update continuity

Coverage alone is not execution truth.
