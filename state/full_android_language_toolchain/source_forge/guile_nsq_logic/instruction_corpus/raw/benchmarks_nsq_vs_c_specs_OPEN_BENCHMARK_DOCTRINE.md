# Open Benchmark Doctrine

## Core rule
This is an open contest, not an artificial parity contest.

## Fairness
- same workload
- same result schema
- same score categories
- native strengths allowed
- no sabotage
- no compensatory handicapping
- no fake semantic inflation for either side

## Important distinction
Equal testing frame does not mean equal architecture.

If one system can naturally express more than the other, that is part of the benchmark result.

## Shared score categories
- parse_ms
- build_ms
- decode_ms
- artifact_bytes
- decoded_bytes
- decoded_records
- replay_hash
- deterministic_repeat_match
- semantic_coverage
- failure_mode

## Interpretation
- C is allowed to be a low-level high-speed system
- NSQ is allowed to be a symbolic semantic system
- whichever system does more, faster, denser, or more reliably should get credit for that
