## Weight and reconstruction rule

Braxon does not treat ordinary full-weight downloading as source truth.

The intended path is:

```text
reconstruction handle
  -> bus record
  -> stamp wake
  -> stored operation/framework
  -> materialization recipe
  -> validation digest
  -> runtime route proof
```

A small file that looks like a pointer is not automatically a failure. It is a failure only if no reconstruction route exists.

If it is named in a reconstruction manifest, bus file, seed pack, wake packet, stamp registry, or materialization recipe, classify it as a reconstruction handle until the route verifier proves or rejects it.

## Hot-live rule

Do not claim hot-live from metadata, manifests, or reserved artifact names alone.

Hot-live requires an executable route proof naming:

1. input handle
2. bus record
3. stamp wake
4. materialization recipe
5. output state
6. validation digest
7. moral invariant check
8. identity preservation check
