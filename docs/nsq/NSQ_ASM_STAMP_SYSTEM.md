# NSQ ASM Stamp System

## Canon rule

ASM is a built-in NSQ runtime surface.

ASM is not an afterthought.

ASM is not a byte escape hatch.

ASM is not allowed to become the real truth underneath NSQ.

ASM is a hot-kernel implementation surface governed by NSQ court routing, canonical parsing, stamps, and semantic digest.

The truth of ASM in this system is not merely raw bytes.

The truth of ASM is parsed instruction meaning, target dialect, runtime platform, stamp identity, source hash, Blake Null semantic digest, and court-valid expansion.

## Stamp law

Any code that will be reused must be saved as a stamp.

This applies especially to:

ASM kernels
C hot loops
Rust runtime helpers
Lisp-style canonicalizers
Python scaffolds
model reconstruction routines
hashing routines
NSQ parser routines
NSQ pack/unpack routines
prime-path routines
language-surface definitions
court routing helpers

A stamp is the reusable unit of source truth.

If code is worth reusing, it is worth stamping.

## Why stamps matter

Stamps make recoding easier because the system can preserve:

exact source
canonical meaning
language surface
dialect
runtime platform
cipher abbreviation
expansion target
hash identity
semantic digest
dependencies
court route

Later recoding can then target the stamp instead of rediscovering the code.

## Cipher law

A cipher token is a short NSQ-friendly abbreviation for a reusable instruction meaning.

The cipher is not a replacement for validation.

The cipher is a compact way to write intent.

The expander can emit familiar code shape when needed.

For example:

MOV means move or register transfer.

LDR means load.

STR means store.

ADD means addition.

SUB means subtraction.

CMP means compare.

B means branch.

BL means call.

RET means return.

PACK means pack NSQ anchors and levers.

UNPACK means unpack NSQ anchors and levers.

HASH means digest/hash kernel.

SCAN means scan loop.

PARSE means parser kernel.

The cipher can expand into AArch64 ASM, x86_64 ASM, C, Rust, or readable pseudocode depending on the target surface.

## ASM role in the stack

ASM is best for:

tight digest loops
scan loops
anchor/lever packing
anchor/lever unpacking
fixed-width dispatch tables
memory-safe bounded copy kernels
SIMD/vector kernels
platform-specific hot lanes
BLAKE3/Blake Null accelerators after canonicalization stabilizes

ASM is not the first place to define dynamic truth.

Dynamic truth should first be specified in docs, parser scaffolds, or readable code.

ASM accelerates stable kernels.

ASM does not replace the parser, linter, or court.

## Canon sentence

Reusable code becomes a stamp; ASM is a native runtime surface; cipher text is allowed as compact intent, but final reuse requires expansion, parse, hash, Blake Null semantic digest, and court validation.
