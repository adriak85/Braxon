# BRAXON Showdown Harvest Plan

## Purpose
Pull only the legacy/runtime/autonomous surfaces that strengthen the singular kernel line before showdown.

## Proof targets
A harvested component is justified only if it improves one or more of:

- boots
- routes
- speaks
- remembers
- guards
- recovers

## Canonical target shape

### Ring 0: kernel
- boot
- restore
- schedule
- dispatch
- persist
- recover
- shutdown

### Ring 1: sovereign seats / system authority
- composer
- linter
- bard
- keeper
- ticketmaster
- archon_gates
- guard
- detective
- sees_all
- seer
- oracle
- crier

### Ring 2: workers / service bodies
- hounds
- disposable agents
- pages
- recoverable pages
- builders
- analyzers
- speech workers
- proof workers

## Pull categories

### Pull now
1. boot / daemon / orchestration
2. CPU/GPU/device capability awareness
3. ingress interfaces (CLI/API/JNI bridge)
4. speech path
5. knowledge/index spine
6. security / telemetry
7. recovery / replay / journaling
8. autonomous kernel behavior patterns that are local-runtime compatible

### Do not pull now
- duplicate constitutions
- duplicate kernels
- cloud-required core dependencies
- extra symbolic hierarchy without runtime effect
- deprecated or parallel entrypoints left uncollapsed

## Acceptance rule
A harvested surface must satisfy all:
- strengthens singular kernel representation
- does not introduce second authority center
- can be attached to a proof target
- can be mapped to Ring 0, 1, or 2
- can be named as keep / adapt / retire

## Harvest decisions
- KEEP = preserve nearly as-is under canonical kernel line
- ADAPT = preserve behavior but move behind kernel/service boundary
- RETIRE = archive and remove from active showdown path

## Immediate showdown priorities
1. unify boot/init
2. unify ingress
3. unify speech
4. unify recovery replay
5. unify device capability reporting
6. expose one operator-visible readiness surface
