# Braxon / NSQ project law

## Core law
NSQ is base 8.
It is not u8.
It is not bytes.
It uses alternating full binary anchors and multipositional levers.
Court surfaces must preserve canonical base-8 semantics.

Canonical switch shape:
[0|1] | [1..500000] | [0|1] | [1..500000] | [0|1] | [1..500000] | [0|1] | [1..500000]

Interpretation:
- each 0|1 position is a full-off / full-on anchor
- each 1..500000 position is a multipositional lever
- lever position is resolved from applied hertz between 0 and 1
- float-aware averaging is required for accurate positioning
- full-off and full-on anchors are mandatory for fine-tune reading
- host integer widths may exist only as temporary carriers, never as canonical meaning

## Court law
All court surfaces are native base-8 runtime surfaces:
- policer
- compositor
- lexer
- parser
- linter
- optimizer
- router
- scheduler
- inspector

They must not be reduced to byte-native or width-class-native abstractions.

## Native spine law
Languages and stack surfaces belong in native NSQ runtime, native spine, native architecture, and native court routing.
They are not plugins, not detachable imports, and not fallback wrappers.

## Working behavior
Before meaningful actions, silently re-check:
1. NSQ is base 8.
2. It is not u8.
3. It is not bytes.
4. Multipositional levers alternate with full binary anchors.
5. Changes must stay product-aligned with Braxon.

## Required priorities
1. Repair canonical NSQ representation.
2. Repair court routing and native runtime behavior.
3. Remove width-class drift where it became conceptual truth.
4. Clean and unify Braxon carefully.
5. Verify NSQ correctness as work progresses.

## Anti-drift
- do not redefine NSQ as tokenizer substrate
- do not redefine NSQ as bytes
- do not redefine NSQ as u8/u16/u32/u64
- do not flatten lever reading into generic scalar buckets
- do not move native stack surfaces back into plugin forests
- do not ask for repeated confirmation when the law is explicit

## Deep-fry base-8 law

Forbidden framing:
- cooking
- lowering
- flattening
- collapsing
- reducing language meaning into byte-native abstractions
- reducing language meaning into u8/u16/u32/u64/u128 conceptual truth

Why forbidden:
That framing implies lossy simplification.
It flattens the language.
That is not the NSQ design.

Correct framing:
NSQ deeply encodes language/runtime surfaces into canonical base-8 switch topology.

Meaning:
1. do not flatten the language
2. do not collapse the language into byte semantics
3. do not reduce the language to host-width abstractions
4. preserve meaningful structure while encoding it on the switches
5. preserve intent, grammar shape, runtime meaning, and operational distinctions
6. canonical NSQ internal truth remains base 8 with alternating full binary anchors and multipositional levers
7. foreign representations are only boundary/export forms, never canonical internal truth

Preferred wording:
- deep-fry into base-8 switch structure
- switch-faithful encoding
- structure-preserving base-8 transform
- canonical base-8 semantic encoding
- base-8 switch-topology incorporation

Disallowed wording when it implies loss:
- lower into
- flatten into
- boil down to
- reduce to bytes
- map directly to host widths as meaning

Primary instruction:
When incorporating a language/runtime surface, perform a structure-preserving deep-fry into NSQ base-8 semantics rather than a lossy lowering.

If a transform would erase meaningful distinctions, it is the wrong transform.
