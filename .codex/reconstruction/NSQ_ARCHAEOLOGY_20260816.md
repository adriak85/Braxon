# NSQ Archaeological Reconstruction — 2026-08-16

## Purpose

This document is a preservation ledger, not a replacement specification. Historical artifacts, duplicates, variants, upstream-looking files, and deprecated states must remain evidence. Similarity is not sufficient grounds for deletion or deduplication.

The reconstruction must recover NSQ before implementing higher-level runtime structures.

## Authority boundary

NSQ is the language / lowest semantic substrate. It must not be conflated with Braxon runtime organization, the cognitive runtime, Citadel, Council Ten, the eight-dimensional gradient, Court/Compositor, or external implementation assistants.

Higher-level structures may be expressed using NSQ without becoming part of NSQ merely because they use it.

The repository's current architecture notes explicitly distinguish the gradient, brain, spine, watermark, metadata, systems, court/compositor, and NSQ substrate. Preserve those distinctions.

## Canonical constraints recovered from repository state

- NSQ is not ordinary binary.
- NSQ is not bytes, u8, u16/u32/u64/u128, or host-width truth.
- NSQ is not a serializer, transport format, DSL, VM trick, macro layer, or prettier syntax over another language.
- NSQ uses base-8 semantics, anchors, charge, levers, stamps, court/compositor authority, and resolved-state behavior.
- Active lever floor is at least 220000; 225370 is a proven effective position count. No exact universal ceiling may be claimed without a proof object.
- The older 1126 lever range is historical/legacy evidence and must not silently become current truth.
- The eight-dimensional gradient is operational, semantic, causal, multidimensional, and execution-relevant; it is not merely metadata, embeddings, or nearest-neighbor lookup.
- Positive and inverse semantic continuity matter.
- Semantic routing must preserve execution causality.
- Stamps are operational wake triggers, not passive labels.
- A valid stamp path is: stamp → wake packet → route resolution → framework retrieval → materialization/reconstruction → execution → persistence/state update.
- Watermarks are operational proof-routing anchors, not decoration.
- Runtime claims require execution/materialization evidence; metadata is not proof.
- Fail-closed behavior is canonical for fake completion, hollow implementations, unresolved wake/routing/materialization, semantic downgrade, fake hot-live state, and broken persistence.

## Historical-state handling

Never collapse artifacts merely because they:

1. have identical or nearly identical text;
2. resemble upstream software;
3. appear to be common infrastructure;
4. carry an older version number;
5. look redundant;
6. describe a concept later represented elsewhere.

Each artifact must retain provenance, path, commit/ref, observed semantics, and relationship to neighboring variants.

## Symbol investigation: `_°`

The historical `_°` notation is unresolved in this pass. It must be preserved as an explicit historical symbol candidate rather than replaced by `∅`, `NULL`, or another conventional null marker without evidence.

The semantic question is still open: determine whether `_°` represented null/absence, an unbound state, a coordinate/state marker, or another NSQ primitive. Parser acceptance and command-line encoding must be investigated separately from semantic meaning.

## Eight-dimensional gradient

Recovered semantic dimensions from prior project state include intent, function, state, emotion, consequence, proof, knowledge, and action. Treat this as historical/current architectural evidence, not proof that these eight names alone exhaust the NSQ language.

The gradient must not be reduced to a flat score or ordinary integer routing. It is intended to participate in stamp wake selection, semantic routing, runtime behavior, reconstruction, execution weighting, and operational selection pressure.

## Runtime / implementation boundary

The repository contains Rust implementations and toolchain infrastructure. These are implementation evidence and build infrastructure, not automatic authority over NSQ semantics.

The current Rust `nsq-citadel` work is therefore preserved as a historical reconstruction lane. It must not be allowed to redefine NSQ or silently turn higher-level Council/Citadel concepts into NSQ primitives.

## Reconstruction sequence

1. Inventory all historical refs, branches, tags, commits, trees, and files.
2. Preserve every artifact and duplicate before interpretation.
3. Build a symbol/grammar ledger, including unresolved notation such as `_°`.
4. Build a semantic ledger separating NSQ primitives from higher-level structures.
5. Build a lever/topology chronology, retaining legacy and active variants.

7. Reconstruct gradient semantics without flattening.
